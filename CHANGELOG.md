# Changelog

Notable changes to Cairn. Dates are release dates; versions follow
[semantic versioning](https://semver.org/spec/v2.0.0.html).

Cairn is pre-1.0, so the storage document schemas are still allowed to change.
When they do, the change and its migration are recorded here.

## Unreleased

### Added

- **Choose which bookmark folders are backed up.** Tick the top-level folders
  to include and the rest never leaves the browser. The selection is read at
  capture time on every path, so it holds for manual and scheduled backups
  alike.
- **Restore part of a backup.** Pick folders or individual bookmarks from the
  pulled document; the selection still lands in exactly one new dated folder,
  so restore stays additive.
- **Scheduled bookmark backups.** Hourly, every six hours, daily, or weekly,
  to any configured backend. Adds the `alarms` permission — a service-worker
  timer cannot survive MV3 idle teardown, so the browser has to hold the
  timer. Failures are reported in the control center rather than discarded,
  because nothing is listening when an alarm fires.
- An **Automation** section in the control center, and a `.crx` attached to
  tagged releases for enterprise policy deployment.

### Fixed

- **Manual "Back up" could upload an excluded folder.** The folder filter
  guarded capture, but the backup uploaded whatever document was already
  stored — so scanning, then excluding a folder, then backing up sent the
  pre-filter tree to the remote. Every backup now captures fresh under the
  selection in force at that moment.
- **A daily schedule could never run.** Re-registering the alarm on every
  browser startup restarted its countdown, so anyone restarting more often
  than their chosen interval never reached a backup. An already-correct alarm
  is now left alone.
- **An unrecognised backup target no longer falls back to WebDAV.** Defaulting
  an interval is an inconvenience; defaulting a target would upload the
  bookmark tree to a backend the user never chose, so the schedule switches
  off instead.
- **An unreadable folder selection no longer means "everything".** Corruption
  used to degrade into an unfiltered backup, which is precisely the data the
  filter existed to withhold. It now fails visibly.
- **`keys/cairn.pem` was being packaged into the Firefox sources archive.**
  WXT builds that archive by walking the working directory and does not read
  `.gitignore`, so a local `npm run zip:firefox` swept in the private key that
  defines the extension id, along with `dist/`. Published archives were never
  affected — CI checks out a tree without those paths — but a locally built
  archive would have leaked the key permanently.
- Rejects an empty restore selection instead of creating an empty dated
  folder, and no longer treats an inherited property name such as
  `constructor` as a valid backup target.

### Changed

- `npm run pack:crx` no longer needs a browser on `PATH`. It uses a pinned
  packer and verifies that the key in `keys/` still yields the established
  extension id before writing anything, because publishing under a different
  id forces a reinstall for every existing user.
- The Compare view now lists every difference it counts. It previously
  reported, for example, "1 version change" with nothing to expand.

## [0.1.1] - 2026-09-03

### Added

- **Self-hosted Firefox updates.** The manifest now carries
  `browser_specific_settings.gecko.update_url`, and `updates.json` is
  generated by `npm version` so the bump commit always lists the new release.

  **If you installed 0.1.0, reinstall once from the latest release.** That
  build shipped without an update manifest, so Firefox has nothing to check
  and it will stay on 0.1.0 forever. Every version after it updates itself.

### Fixed

- The release workflow's manual re-run path never worked: it read the branch
  name instead of the tag it was given, so a re-run would build the wrong ref
  and then fail its own version check.
- A failed Mozilla signing step no longer publishes a release with no
  installable Firefox artifact.
- The manifest version is derived from `package.json`, so `npm version` is the
  only place a release is bumped.

## [0.1.0] - 2026-09-02

First release. Renamed from `hsync`.

### Added

- Extension inventory capture through the browser's management API, with
  automatic recapture on install, removal, enable, and disable, and Cairn
  excluded from its own record.
- Comparison of two inventories: extensions only on the remote, only here,
  version differences, and enabled-state differences.
- Bookmark backup and additive restore into a new dated folder.
- Gitea, GitHub and GitHub Enterprise, WebDAV, and S3-compatible backends,
  with conditional writes (ETag or blob SHA) so concurrent writes cannot
  silently overwrite each other.
- A multi-device inventory format where each device keeps its own section, and
  an explicit one-time action to convert an existing remote to it.
- Runtime host-permission requests scoped to the endpoint you configure.
